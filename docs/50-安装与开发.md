# 50 — 安装、构建与开发循环

> 实操手册。环境事实:开发/会话守护在 node-a(10.13.15.3,chlamydomonoss1)本机;VS Code 与 pi-web 前端也在该机访问;**从浏览器验证一律用 `http://10.13.15.3:8504`,不要用 127.0.0.1**。用户 shell 为 fish(写脚本用 Python 文件,不用 heredoc)。

| pi-web      | ≥ 1.202610.1,sessiond 以 systemd user 服务运行,gateway :8504                                | `systemctl --user status pi-web-sessiond`、浏览器开 `http://10.13.15.3:8504` |

**验证身份防串机**:浏览器验证前先 `hostname` + `curl /api/health` 确认命中 node-a(本机 127.0.0.1:4099 上另有 node-b 旧实例,勿混淆)。

## 2. 构建本包(`projects/pi-comfyui/`)

```sh
cd projects/pi-comfyui
npm install          # dependencies: ws, jiti, lit; peerDependencies(*): @earendil-works/pi-coding-agent, typebox
npm run build        # esbuild → dist/plugin/browser/index.js + dist/plugin/server/index.js
```

- 扩展部分(`src/extension/`)由 pi 加载器即时转译,**不进构建产物**。
- 浏览器与服务器插件入口**必须构建**:pi-web 不编译插件源码(官方原则:安装包内必须是构建后的 JS;`browserRoot` 内全部资产浏览器可见,上限 4096 文件/16MiB,排除 node_modules)。
- `dist/plugin/browser` 即 `manifest.browserRoot`;lit 建议打进 bundle(esbuild external=宿主不可用,浏览器插件拿不到宿主依赖共享)。

## 3. 安装

### 3.1 本地开发安装(pi-web 侧)

官方做法(官方指南 "Local development"):

```sh
mkdir -p ~/.pi-web/plugins
ln -sfn /root/ai/chlamydomonos-harness/projects/pi-comfyui/integration/dist /…   # 见下方说明
```

> 实际上符号链接目标是**包根**(含 `package.json` 与 `piWeb.plugins` 声明;目录扫描在包根发现清单)。正确命令:

```sh
ln -sfn /root/ai/chlamydomonos-harness/projects/pi-comfyui-integration/projects/pi-comfyui ~/.pi-web/plugins/pi-comfyui
```

- 若设置了 `PI_WEB_DATA_DIR`,用 `$PI_WEB_DATA_DIR/plugins` 代替。
- 无需重建 pi-web;改代码后只需重建本包。

### 3.2 正式安装(pi 包)

两种等价方式(官方 "Install and manage"):

```sh
# 方式 A:CLI(推荐;会写入当前 profile 的 packages)
pi install /root/ai/chlamydomonos-harness/projects/pi-comfyui     # 全局/个人
pi install -l ./projects/pi-comfyui                               # 项目本地(需要项目 trust)

# 方式 B:profile settings(~/.pi/agent/settings.json)
{ "packages": [ "/root/ai/chlamydomonos-harness/projects/pi-comfyui" ] }
```

- pi-web 从已安装的 pi 包里**发现 `piWeb.plugins`**;pi 则各自加载 `pi.extensions`——**两边都要生效**才能完整(官方:仅启后端不算完整)。
- 正式流程:**Settings → Pi packages** 里安装/更新/移除(npm、git、local 源均可),然后 **Settings → PI WEB plugins** 启用/停用并查看是否 active 或需要重启。

### 3.3 启用与刷新对照表(官方规则)

| 变更                                  | 需要的动作                                                                                                                                                         |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 浏览器侧插件代码更新                  | 重建本包 → **刷新浏览器页面**(无需重启)                                                                                                                            |
| 服务器侧插件代码更新                  | 重建本包 → **重启目标 sessiond → 刷新浏览器**:`systemctl --user restart pi-web-sessiond`(官方:重启 sessiond 会打断其托管中的会话,务必从会话外、确认无活跃任务时做) |
| pi 扩展/技能/提示词变更               | 每个空闲会话里跑 `/reload`                                                                                                                                         |
| 声明的 `defaultEnabled`/Settings 开关 | 按 server-backed 与否套上两行                                                                                                                                      |

重启 sessiond 之后 Settings 里才能看到 desired 与 active 状态对齐;在那之前面板可能显示"需要重启"。

### 3.4 故障恢复(官方命令,本机执行)

```sh
pi-web plugins disable comfyui --restart
pi-web plugins safe-start show
pi-web plugins safe-start set bundled-only --restart   # 只留内置插件
pi-web plugins safe-start clear --restart              # 修复后恢复常规启动
```

服务端日志:`pi-web logs`;浏览器问题看浏览器 console。

4. 验证点清单:

    - 用户在执行中发 stop → 会话停止 → 终态卡片"已取消"(非错误);
    - 关掉 ComfyUI 再 generate → 收到连接错误,工具失败,面板卡片 failed;
    - 多标签页同 session 开面板 → 两边同步收帧;
    - **面板在 http://10.13.15.3:8504 下打开**,验证产物 img/video/audio 能预览。

## 5. 开发注意(踩坑预防)

- 会话 daemon 里的插件代码与浏览器是两份;浏览器 console 报"module not found"通常是 `browserRoot`/入口路径错。
- events 无回放:面板打开晚于任务开始时,靠服务端 `history` 打底帧恢复(30 §3.3)。
- 事件先后:服务端先 connect+subscribe,后发 cmd(30 §3.1);扩展先连 WS 后 POST /prompt(10 §3.1)。这两处的顺序错不会立刻报错,只会"收不到帧",调试时先查顺序。
- 大产物不进上下文,只走文件系统;若模型 reply 里出现 base64,说明实现把最终图也塞进了 content,**违背 D-economy**,修。
- ComfyUI 手动改配置/装包后需要重启 ComfyUI 本身(gpu-manager 不管理其进程),`systemctl --user restart` 由用户决定。
- 测试生成器参数错误路径时,故意传 `seed:-1` 之类,确认 400 node_errors 文本可读。

## 5.1 实际验收记录(2026-10-09,真机全绿)

环境:ComfyUI v0.38.0 @ gpu-manager 代理 :4100(亦可用 :8188 直连);本地无 `sd_xl_base`,示例 checkpoint 用 `waiIllustriousSDXL_v160.safetensors`(插画风格)。验收工作区 `/root/pi-comfyui-accept`,验收脚本 `projects/pi-comfyui/scripts/accept.mjs(用法:`node scripts/accept.mjs <ws> <baseUrl>`,自动 cp 示例生成器到 `<ws>/.pi/comfyui/generators`)`。

- **扩展脚本化验收(ALL PASSED,7 组)**:status(devices>0)/list(2 valid)/txt2img completed+落盘+进度帧/,img2img(以 r1 输入复用)/cancel→cancelled/overflow 第三入队拒绝/错误三路径(未知生成器、缺 prompt、`output.dir:"../escape"`)。frames 108,preview 帧 72。
- **pi-web 面板端到端**:`pi install <包根>` + symlink `~/.pi-web/plugins/pi-comfyui` + `systemctl --user restart pi-web-sessiond`(打断托管会话,已获用户确认)→ 浏览器 `http://10.13.15.3:8504`(注意双机拓扑,不能用 127.0.0.1)→ 面板出现 summary/生成器 2 个/历史/画廊;真实 pi 会话里 `comfyui_generate` 成功产 `live-e2e-2.png`,面板同步:生成器列表(会话 generators 帧)、历史 1 条、画廊 4 文件、状态"空闲"。
- 过程中修复的实现 bug(与 docs 冲突以实测为准):
    1. `runJob` 里生成器按 `build(params, ctx)` 两参调用(此前误传单参 ctx,ctx.token 崩);
    2. `ComfyWsClient` 构造不自动连接,`runJob` 必须先 `ws.start()` 再 `waitForWsOpen`(曾致 WS 永远超时走轮询兜底);
    3. docs/20 §2 示例 CLIPTextEncode `clip` 接线应为 checkpoint 输出口 **1(CLIP)**(口 0 是 MODEL;口 2 是 VAE),`['1',0]` 会被 ComfyUI 400 校验拒绝——§2 已修;
    4. `defaultGeneratorDir` 固定为 `<workspace>/.pi/comfyui/generators`(与 §4.1 路径一致)。
- 面板"生成器——暂无"仅出现在**工作区尚无 pi 会话**时(生成器列表来自会话的 generators 广播,非服务端扫描),属预期。

## 6. 发布(可选)

- `package.json` 加 keyword `pi-package`(pi 目录约定),name 建议 `@chlamydomonos/pi-comfyui-local` 或 `pi-comfyui`。
- 发布物:源码 + `dist/`(插件构建产物)+ `docs/`(不含);peerDependencies 保持 `"*"`。
- pi-web 插件目录扫描在**包根**找 `piWeb.plugins`,与"符号链接本地开发"和"npm 安装"两种来源兼容(目录扫描/已装 pi 包双重发现,catalog 会去重;冲突时 Settings 显示警告)。
- 版本对应:升级 pi / pi-web 大版本时,插件 apiVersion(browser 4 / server 3)可能变化——跟官方 plugins.md 的契约版本走,无兼容垫片。
