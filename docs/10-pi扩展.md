# 10 — Pi 扩展规范(工具 + 生成器装载 + 配置)

> 本篇定义 `pi-comfyui` 包中 pi 扩展部分的完整行为契约。实现时以本篇 + 20(生成器指南)+ 40(ComfyUI API)为准。
> 前置阅读:00-架构总览。已确认 API:Pi v1.1.0 扩展系统(`registerTool` / `pi.events` / `ctx.cwd`,来源 `pi-coding-agent@1.1.0` 类型定义与官方 extensions.md)。

## 1. 包与入口

- `package.json` 声明 `"pi": { "extensions": ["./src/extension/index.ts"] }`(见 00 §7);pi 通过 jiti 直载 TS,扩展部分**无需构建**。
- 入口为 default factory:

```ts
import type { ExtensionAPI } from "@earendil-works/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  // session_start 才能拿到 ctx;工厂内禁止长驻资源(pi 生命周期要求)
  pi.on("session_start", ...)
  pi.registerTool(...)
}
```

生命周期要点(pi 文档原文约束):**工厂内不得启动进程/套接字/定时器**;WS 连接等长驻资源只在工具执行期间创建并关闭;`session_shutdown` 中做幂等清理(终止未完挂起任务标记、关闭残留 WS)。

## 2. 配置(D7)

### 2.1 文件与优先级

| 层级   | 路径                                         | 作用             |
| ------ | -------------------------------------------- | ---------------- |
| 全局   | `~/.pi/agent/comfyui.json`                   | 所有会话的默认值 |
| 工作区 | `<工作区>/.pi/comfyui.json`(即 `ctx.cwd` 下) | 覆盖全局         |

合并规则:浅合并(top-level 键逐项覆盖);任一文件缺失即跳过;解析失败时**记 warning 并继续**用默认值 + 已解析部分(pi 文档惯例:配置错误不致命)。每次工具调用时重新读取,文件 mtime 相同则命中内存缓存。

### 2.2 字段(默认值)

```jsonc
{
    "baseUrl": "http://127.0.0.1:4100", // gpu-manager 入口(comfyui app),不要直连 8188
    "timeoutMs": 900000, // 单任务从提交到终结的硬上限,超时→interrupt+失败
    "outputDir": "comfyui-output", // 工作区内相对目录
    "previewMaxSize": 512, // 预览帧最长边目标(px;仅在装了 sharp 时缩放)
    "previewIntervalMs": 800, // 预览帧发往 pi.events 的最小间隔
    "previewBytes": 196608, // 单帧 base64 上限(192 KiB),超限丢帧
    "tools": ["generate", "list"], // 可加 "status"、"cancel"
    "maxQueue": 2, // 每会话排队上限(超过直接拒绝)
}
```

注意:**没有** `autoPreview`/注入类开关(D5 已定:绝不注入节点);**没有** toolMode(D3 已定:方案 B 固定)。

### 2.3 读取来源补充

扩展仅读上述两份 JSON;不从 pi settings、环境变量取配置(gpu-manager 地址写死在配置里,便于跨机部署修改)。校验失败的键记 warning 忽略。

## 3. 工具集(D3:方案 B)

统一约定:

- `namespace: { name: "comfyui", description: "ComfyUI 生成工具;生成器由用户在工作区 .pi/comfyui/generators 定义" }`
- 每个 `parameters` 必须是 TypeBox `Type.Object`(**必须是 object schema**,pi 硬性要求)。
- 结果统一形状:`{ content: [{type:"text", text}], details, structuredContent?, isError? }`。**最终 content 永远只有文本**(落盘路径清单),不内嵌最终图片——图片内容会进上下文吃 token;过程中的预览图只走 `onUpdate`(部分结果不进上下文)。
- 全部工具同时发 `pi.events.emit("pi-comfyui", frame)`,定义见 30 §5(共享 protocol.ts)。

### 3.1 `comfyui_generate`

```ts
parameters: Type.Object({
    generator: Type.String({ description: '生成器名称=comfyui_list_generators 返回的 name' }),
    params: Type.Optional(
        Type.Record(Type.String(), Type.Unknown(), {
            description: '传给该生成器的参数;结构以 list_generators 返回的 params schema 为准',
        }),
    ),
    output: Type.Optional(
        Type.Object({
            dir: Type.Optional(Type.String({ description: '产物目录(工作区内相对路径),默认为配置 outputDir' })),
            name: Type.Optional(Type.String({ description: '产物文件名主干(不含扩展名);多产物自动追加 -2、-3…' })),
        }),
    ),
});
```

**execute 流程**(同步语义,D4):

1. **前置检查**:生成器装载(§4);若有同类任务在跑→进入会话内 FIFO 队列(`maxQueue` 上限,超限返回错误结果,提示稍后再试);`output.dir` 做路径安全校验(禁止 `..` 逃逸出工作区)。
2. **排队帧**:发 `{kind:"job", state:"queued", …}`;轮到自己时发 `state:"running"`。
3. **连线**:生成 `clientId = uuid`;连 `ws://${hostFrom(baseUrl)}/ws?clientId=<clientId>`;作为**首条消息**发送 `{"type":"feature_flags","data":{"supports_preview_metadata": true}}` 以获得带元数据的预览帧(帧格式见 40 §4)。**必须先连 WS 再提交**,因为 `execution_start/progress/executed/execution_error` 只发给提交时的 `client_id`(server.py 源码确认:`server.client_id` 定向)。
4. **提交**:`POST /prompt`,body `{ prompt: graph, client_id: clientId, extra_data: { pi_generator: <生成器名> } }`,`prompt_id` 不传(服务端铸造 UUID)。HTTP 400 → 解析 `error` + `node_errors` → **立即失败**,content 给精简错误(“节点 X:错误信息”),`details` 带完整 `node_errors`;HTTP 成功但 `node_errors` 非空 → 继续执行,作为 warning 附在最终结果。
5. **跟踪循环**(WS 事件 + 兜底轮询):
    - `progress` / 二进制 b_preview → 归一化后:
        - `onUpdate({content:[{type:"text",text:"KSampler 3/20"}, …预览帧(若有)], details})`——**限频** `previewIntervalMs`;
        - `pi.events.emit("pi-comfyui", {kind:"progress"…})` 与 `{kind:"preview"…}`(缩放/限频/尺寸上限,见 §6)。
    - `executing {node:null}` 或 `execution_error` / `execution_interrupted`,**并以** 2s 间隔兜底轮询 `GET /history/{prompt_id}` 的 `status.completed`(WS 掉线也能终结)。
6. **异常处理**:
    - abort signal(用户停止)→ `POST /interrupt {"prompt_id"}`(定向,server.py:1168 支持)→ 等待 `execution_interrupted`(最多 5s)→ 结果 `state:"cancelled"`(非 isError)。**注意**:中断只是停止当前执行,ComfyUI 队列中的其他任务不受影响。
    - `timeoutMs` 超时 → 同上 interrupt → `state:"failed"`,isError,content 说明超时。
    - WS 意外断开 → 自动重连一次(同一 clientId 会顶掉旧连接,server.py:272 语义);持续断线则完全靠轮询兜底。
7. **收割落盘**(§5):`GET /history/{prompt_id}` → 遍历 `outputs` → 形状匹配(值是含 `filename`+`type` 字段的对象数组)→ `GET /view?filename&subfolder&type` 下载 → 写入工作区 → 得到相对路径清单。
8. **收尾**:发 `{kind:"job", state: 终态}` + `{kind:"outputs", files:[…]}`;关闭 WS。
9. **最终结果**:

```
content(文本模板,精简):
✅ txt2img-sdxl — 2 个产物,执行 8.4s
- comfyui-output/sunset.png (1.4 MB, image/png)
- comfyui-output/sunset-2.png (1.3 MB, image/png)
(warning:node_errors 非空时附一行)

details / structuredContent:
{ jobId, generator, state: "completed", files: [{path, size, mime, subfolder?, type?}],
  promptId, timings: {queueMs, runMs}, error? }
```

失败模板(content 仍要解释,`isError:true`,details 带 `state:"failed"` + `error`):

```
❌ txt2img-sdxl 失败(12.1s):节点 KSampler 校验失败——seed 非法
```

`outputSchema` 声明与 `structuredContent` 同构(`{jobId, state, files, error?}`),供 codemode 脚本消费。

### 3.2 `comfyui_list_generators`

```ts
parameters: Type.Object({}); // 无参
```

结果:枚举 `<工作区>/.pi/comfyui/generators/*.js`(不含 `.pi/comfyui/generators` 子目录内的再下一层——扁平一层,D2),对每个文件:装载并校验。

content 文本(**模型主要靠它了解参数**,格式紧凑):

```
3 个生成器:
- txt2img-sdxl:SDXL 文生图。prompt*, negative?, width?1920, height?1080, steps?30, seed?
- img2img-sdxl:…(入参 image 为工作区内图片路径)
- tts-openvoice:…
0 个无效文件(若有:列出文件名+原因一行)
```

`details`:完整数组 `{name, title, description, paramsSchema, valid, error?}`,便于 pi-web 面板"刷新生成器"。同时发 `{kind:"generators", list:[…]}` 事件帧。

> token 预算:每生成器一行;`description` 由生成器作者控制(指南 §3 建议每行 ≤ 160 字符)。生成器数量多时,模型先 list 再 generate,两步成本远低于 per-generator 常驻声明(方案 B 本意)。

### 3.3 可选工具:`comfyui_status`、`comfyui_cancel`(默认关闭)

配置 `tools` 含键时才注册(pi 工具只能注册不能注销,故注册动作在 `session_start` 里按配置决定;会话中途改配置要 `/reload`)。

- `comfyui_status`:无参。读 `GET /queue` + `GET /system_stats`,content 一行文本(队列剩余数/是否在跑/VRAM free),details 完整 JSON。**不感知 gpu-manager lane 状态**(proxy 对 comfyui 全旁路,忙闲就是 `/queue`)。
- `comfyui_cancel`:`{ jobId?: string }`。对**本会话**当前任务发 `/interrupt`(无参则全局);content 报告结果。它也接受浏览器面板经命令帧触发的取消(§7),工具本体供 Agent 主动取消用。

### 3.4 token 经济核对(方案 B 全景)

| 恒定开销          | 内容             | 规模             |
| ----------------- | ---------------- | ---------------- |
| generate 声明     | 参数 3 项 + 描述 | ~200 token       |
| list 声明         | 无参             | ~60 token        |
| list 结果(一次性) | 每生成器一行     | ~60 token/生成器 |
| generate 结果     | 路径清单         | 短文本           |

## 4. 生成器装载器(D2)

- 位置:`<ctx.cwd>/.pi/comfyui/generators/*.js`;文件名(去 `.js`)即默认 `name`;不递归子目录。
- 装载:读文件文本 → jiti 编译为模块(生成器**不允许顶层 import**——装载器做语句级扫描:行首 `import …`/`export import …`、`… = require(…)`、`import(…)` 动态调用即拒绝并报无效原因;代码/注释中仅出现 import 一词不受影响。保持自包含)。
- 校验(不通过→“无效生成器”,list 中给原因):default 导出对象;`name?` 字符串且匹配 `[a-z][a-z0-9-]{0,63}`;`title`/`description` 字符串;`params` 为 JSON Schema 对象且 `type:"object"`;`build` 为函数。
- 执行:`build(params, ctx)`,其中参数已通过包内 mini validator 按 `params` schema 校验并应用 `default`。> **实现偏离(已与 docs 冲突处理规则一致)**:TypeBox 的 `Value.Default` 对纯 JSON Schema 对象不生效,故不直接用 TypeBox Value;改用包内 `validateAndApplyDefaults`(JSON Schema 子集:`type`/`enum`/`minimum`/`maximum`/`required`/一层嵌套对象;`default` 深合并;未知键透传)。工具注册仍用 TypeBox `Type.*` 构造参数 schema(typebox 运行时映射到 pi 内置)。`ctx`:

```ts
interface GeneratorContext {
    workspace: string; // = ctx.cwd(pi ExtensionContext.cwd,已核实存在)
    resolvePath(rel: string): string; // 工作区内相对 → 绝对路径(供路径加载节点)
    token: string; // 6 位随机串,建议用于 filename_prefix 唯一化
    now: string; // ISO 时间戳
}
```

- 返回:`{ prompt: <API 格式 graph 对象> }`(graph 结构见 40 §3);多余的返回键忽略。build 抛错→工具失败,content 带原始错误消息(这对生成器作者调试最重要)。
- mtime 缓存编译产物;文件删除后缓存失效。
- 信任模型:生成器与扩展同进程同权限(pi 官方扩展信任模型),用户自担其代码风险;装载器的 import 禁令只是工程约束不是安全边界(写进文档 20)。

## 5. ComfyUI 客户端(`comfy-client.ts`)

- HTTP:全部经 `baseUrl`(默认 gpu-manager 4100)。超时:提交 30s、`/view` 单文件 120s、`/history` 轮询 10s。
- WS:每任务一条连接;首条消息发 feature_flags;解析文本 JSON 帧(10 种,见 40 §4)与二进制帧(`[4B event][payload]`,预览帧两种:裸 `1` 与带元数据 `4`,字节布局见 40 §4.3)。
- 事件→内部状态映射:
    - `execution_start` → running(阶段:开始执行)
    - `executing {node!=null}` → 更新当前节点名
    - `progress {value,max}` → 进度条
    - `executed` → 该输出节点完成(可提前拿到 outputs,但以 history 为准)
    - `execution_error` → 失败,提取 `exception_message` + `node_type`
    - `execution_interrupted` → cancelled
    - `executing {node:null}` → 执行完所有节点(等待 history 确认)
    - 其他(`status`/`progress_state`/`execution_cached`/`feature_flags`)→ 忽略(debug 日志)
- 断线:一次自动重连(3s 退避);再失败→降级纯轮询模式并日志警告。

## 6. 预览帧处理(D5)

- 来源:部署已开 `--preview-method auto`,执行期 ComfyUI 主动推 b_preview 二进制帧;扩展**只解析不注入**。
- 解析:优先 `4 PREVIEW_IMAGE_WITH_METADATA`(`[4B len][JSON meta][图bytes]`,meta 含 `image_type` mimetype);兼容 `1 PREVIEW_IMAGE`(`[4B type_num 1=JPEG/2=PNG][图bytes]`,quality 95)。
- 后处理(按顺序):
    1. 尺寸上限:`previewBytes` 超限 → 若环境存在 `sharp`(包的可选依赖,特征检测)则缩到 `previewMaxSize` 再判;仍超限→**丢帧**(记 debug)。
    2. 限频:`previewIntervalMs` 内只发最新一帧(events 总线与 onUpdate 共用同一限频器,避免双通道×2 流量)。
- 发射:
    - `pi.events.emit("pi-comfyui", { kind:"preview", jobId, mime, data: base64 })`
    - `onUpdate({ content:[{type:"text",…},{type:"image", mimeType, data}], details })`
- **收不到预览帧是正常情况**(D5:如部署环境未开 `--preview-method`、或节点本身不产生预览):UI 层(面板)对"从未收到 preview 帧"直接不显示预览区,不显示占位错误。

## 7. 对 pi.events 的命令监听(浏览器面板 → 扩展)

`session_start` 时订阅并跟踪退订(pi 事件总线无回放,须先订阅后发;服务端插件负责保证发在订阅后):

```ts
const off = pi.events.on('pi-comfyui', (data) => {
    // data: {kind:"cmd", action:"cancel"|"refresh", jobId?}
    if (data?.kind === 'cmd' && data.action === 'cancel') cancelActive(data.jobId);
});
```

`session_shutdown` / `session_start` 前调用退订(幂等)。服务端插件的对应发送见 30 §6。

## 8. 会话内任务管理

- 每会话:单活动任务 + FIFO 等待(`maxQueue`);任务记录(内存):`{jobId, generator, promptId, state, startTime}`。
- 会话关闭(`session_shutdown`):关 WS、清队列;**不** interrupt 正在跑的远端任务(它属于 ComfyUI 队列,继续执行无妨,history 兜底可查,但本会话不再收割)。
- jobId:`pi-<短随机>`;与 ComfyUI 的 `prompt_id`(UUID)分开存,映射关系进 details。
- abort 处理:pi 传给 execute 的 signal 触发 §3.1-6 的 interrupt 流程;排队中的任务被 abort → 直接从队列移除,不发任何 HTTP 请求。

## 9. 错误映射总表

| 情形                            | 终态            | isError        | content 要点                                               |
| ------------------------------- | --------------- | -------------- | ---------------------------------------------------------- |
| HTTP 400(node_errors)           | failed          | ✅             | 精简节点错误;details 完整 node_errors                      |
| execution_error                 | failed          | ✅             | 节点名+异常消息                                            |
| execution_interrupted(用户停止) | cancelled       | ❌             | “已中断”                                                   |
| 超时                            | failed          | ✅             | 超时时长;已尝试 interrupt                                  |
| 生成器装载/build 抛错           | failed          | ✅             | 原始错误消息(生成器作者调试)                               |
| 队列满                          | failed          | ✅             | “已有 N 个任务排队,请稍后再试”                             |
| 收割阶段 /view 失败             | completed(降级) | ❌(带 warning) | 列出已成功的文件+失败项                                    |
| history 无任何可收割产物        | completed(空)   | ❌             | “任务完成但没有可识别的输出文件(检查生成器是否有输出节点)” |

## 10. 与 pi-web 插件共享的协议

全部帧类型/频道名常量定义在 `src/shared/protocol.ts`,扩展、服务端插件、浏览器插件三方 import 同一文件(单包优势,D1)。频道名固定 **`"pi-comfyui"`**。协议定义详见 30 §5;扩展侧只做 emit(出)与 cmd 解析(入)。
